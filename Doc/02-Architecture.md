## 1. 架构总览

nine_tailed_fox 采用 **混合架构**：Web 前端（Vue SPA）负责编辑/管理/预览，云端服务负责业务逻辑与 AI 编排，**Milvus** 承载记忆与向量检索，本地 Agent 承担重计算（图像/视频生成，ComfyUI）。AI 能力通过 Provider 抽象层统一接入，**图像/视频以本地 ComfyUI 为主**，云端 API 作备选。

```
┌─────────────────────────────────────────────────────────────┐
│                      用户浏览器                              │
│  ┌───────────────────────────────────────────────────────┐  │
│  │              Web 前端 (Vue 3 SPA)                     │  │
│  │   剧本编辑器 · 分镜工作台 · 视觉设定 · 素材库 · 预览    │  │
│  └───────────────────────────┬───────────────────────────┘  │
└──────────────────────────────┼──────────────────────────────┘
                               │ HTTPS / WebSocket
┌──────────────────────────────▼──────────────────────────────┐
│                    云端服务层 (Server)                       │
│  ┌────────────┐  ┌────────────┐  ┌────────────────────┐    │
│  │ 业务逻辑    │  │ AI 编排    │  │ 任务调度           │    │
│  │ (剧目/剧本/ │  │ (LangChain │  │ (异步任务队列/     │    │
```

## 2. 分层设计

### 2.1 Web 前端层

| 项 | 说明 |
|----|------|
| 职责 | 用户交互、内容编辑、素材预览、任务状态展示（Web 形式展示） |
| 技术栈 | **Vue 3 + TypeScript**（Vite 构建，纯 SPA） |
| 状态管理 | 轻量状态（**Pinia**）+ 服务端状态（**@tanstack/vue-query**） |
| 编辑器 | 剧本编辑器基于结构化富文本（**@tiptap/vue-3**） |
| UI 组件库 | **Element Plus**（暗色模式，影视创作场景） |
| 实时通信 | WebSocket / SSE 接收任务进度推送 |
| 部署 | 构建产物静态托管（Docker + Nginx/Caddy），可部署至云端或本地 Agent 同机 |

> 前端策略（2026-08-19）：功能自研（Vue 3），**UI/交互先对齐 Toonflow 设计风格**（深色影视工作台、Agent 流式对话、无限画布工作台、设置中心分组），详见 06-Tech-Stack.md §1.0。

### 2.2 云端服务层 (Server)

| 子模块 | 职责 |
|--------|------|
| 业务逻辑 | 剧目/剧本/分镜/设定/素材的 CRUD 与关系管理 |
| AI 编排 | Prompt 构造、Provider 路由、生成结果处理 |
| 任务调度 | 异步任务队列、进度回传、失败重试 |
| 数据存储 | 元数据存 DB，素材文件存对象存储/本地文件系统 |
| 认证授权 | 单人优先：本地账号即可；预留多用户扩展 |

**技术栈（已定版，参照 waoowaoo）**：
- Node.js + **Express 5**（REST API）+ TypeScript（tsx 运行）
- 任务队列：**BullMQ + Redis**（+ Bull Board 监控），独立 worker 进程
- 数据库：**Prisma + MySQL**（单机模式可切 SQLite，waoowaoo 双 schema 同款）
- 对象存储：本地文件系统为主 + **COS/S3 双 SDK**；图像处理 sharp
- 记忆/向量检索：**Milvus**（standalone，Docker 部署），业务元数据存 MySQL、向量存 Milvus，通过业务对象 ID 关联

### 2.3 本地 Agent 层

| 项 | 说明 |
|----|------|
| 职责 | 承担 GPU 密集的重计算：图像/视频生成、本地模型推理 |
| 核心能力 | 对接 **ComfyUI**（本地 `H:\ComfyUI\ComfyUI-V18.1`）进行图像/视频生成；可扩展本地 LLM/TTS |
| 通信 | 与云端服务通过 HTTP/WebSocket 通信，接收任务、回传进度与结果 |
| 部署 | 用户本地机器，需具备 GPU（视频生成场景） |
| 数据 | 生成的大文件默认存本地，元数据回传服务层 |

**本地 Agent 设计要点**：
- 作为「任务执行器」，不承载业务逻辑
- 通过 ComfyUI 的 API 接口提交工作流（workflow JSON）
- 支持自定义工作流模板，适配不同生成场景（角色图/场景图/视频片段/图片编辑/数字人）
- 健康检查与心跳，云端服务感知 Agent 在线状态
- **图像/视频生成以本地 ComfyUI 为主路径**，云端 API 作为降级备选

### 2.4 AI 能力层 (Provider 抽象)

独立设计文档见 [05-AI-Provider-Design.md](./05-AI-Provider-Design.md)。

核心思路：
- 每类 AI 能力（文本/图像/视频/语音）定义统一接口
- 每个接口可有多个 Provider 实现（云端 API / 本地 ComfyUI）
- 用户可按能力维度配置选用哪个 Provider
- 支持降级与回退策略

## 3. 模块划分

### 3.1 业务模块

```
nine_tailed_fox
├── project-hub        项目工作台     (剧目管理、进度看板)
├── script-studio      剧本创作       (选题/大纲/分集/分场)
├── storyboard         分镜系统       (拆镜/镜头编辑/故事板)
├── visual-assets      视觉设定       (角色卡/场景卡/风格)
├── av-generation      音视频生成     (视频/TTS/配乐)
└── asset-library      素材资产库     (分类/版本/检索/导出)
```

### 3.2 模块关系

```
project-hub ──┬──> script-studio ──> storyboard ──> av-generation
              │                           │              │
              │                           ▼              ▼
              │                    visual-assets    asset-library
              │                           │              ▲
              └───────────────────────────┴──────────────┘
                         (所有模块产物入库)
```

- `project-hub` 是顶层入口，串联其他模块
- `script-studio` 的剧本是 `storyboard` 拆镜的输入
- `visual-assets` 为 `storyboard` 与 `av-generation` 提供一致性约束（角色/场景形象）
- `av-generation` 产出的素材进入 `asset-library`
- 所有模块的生成物均可入库到 `asset-library`

## 4. 数据流（典型链路）

以「剧本 → 分镜 → 视频」为例：

```
1. 用户在 script-studio 完成分场剧本
     │
     ▼  (剧本数据)
2. storyboard 模块调用「AI 拆镜」→ 生成镜头序列
     │
     ▼  (镜头数据)
3. visual-assets 已就绪的角色卡/场景卡作为约束
     │
     ▼  (镜头描述 + 视觉约束)
4. storyboard 调用「故事板生成」(图像 Provider) → 分镜图
     │
     ▼  (分镜图 + 镜头描述)
5. av-generation 调用「视频生成」(视频 Provider)
     │   ├── 云端 API 路径：直接调用云端
     │   └── 本地路径：任务下发至本地 Agent → ComfyUI
     │
     ▼  (视频片段)
6. 素材入库 asset-library，关联至对应镜头
```

## 5. 技术栈选型（建议）

| 层 | 选型 | 选型理由 |
|----|------|----------|
| 前端框架 | **Vue 3 SPA**（Vite 构建） | 用户指定；轻前端，纯编辑/管理/预览；区别于 waoowaoo 的 Next.js 全栈 |
| 前端语言 | TypeScript | 类型安全，长期可维护 |
| UI 组件库 | Element Plus（备选 Naive UI） | Vue 生态最主流，暗色模式齐全 |
| 富文本编辑 | @tiptap/vue-3 | 结构化剧本编辑，可扩展节点类型 |
| 状态管理 | **Pinia + @tanstack/vue-query** | 轻量 + 服务端状态分离 |
| 无限画布（规划） | **@vue-flow/core（Vue Flow）** | Toonflow 同款实证（见 06 §1.4 与 08 文档）；LogicFlow/自研 Canvas 为备选 |
| AI 编排 | Python LangChain + LangGraph | 多步工作流编排（剧本→拆镜→资产→生成），独立 FastAPI 服务，Tool 封装 ComfyUI |
| 记忆/向量库 | **Milvus**（standalone） | 用户指定；素材语义检索、角色一致性召回、项目记忆（langchain-milvus 接入） |
| 后端框架 | Express 5（TypeScript） | 参照 waoowaoo（其 worker/board 即 Express 5），AI 编排独立 Python 服务 |
| 数据库 | Prisma + MySQL（单机可 SQLite） | 参照 waoowaoo（Prisma 6 + mysql2，双 schema） |
| 任务队列 | BullMQ + Redis + Bull Board | 参照 waoowaoo，异步生成任务 + 可视化监控 |
| 本地生成 | **ComfyUI**（主路径） | 本地 V18.1 已部署；图像/视频生成以本地为主，云端备选 |
| 实时通信 | WebSocket / SSE | 任务进度推送、AI 流式输出 |
| 存储 | 本地 FS + COS/S3 双 SDK + sharp | 参照 waoowaoo（cos-nodejs-sdk-v5 + @aws-sdk/client-s3） |
| 部署 | **Docker Compose 全栈** | 前端/后端/AI/MySQL/Redis/Milvus/ComfyUI 统一编排 |
| 工程化 | ESLint + Husky + Vitest + guards 体系 | 参照 waoowaoo 的架构守卫脚本（API 契约/能力目录/媒体契约） |

## 6. 部署架构

### 6.1 单机部署（MVP，Docker Compose 全栈）

```
┌─────────────────────────────────────────────────────┐
│              用户本机（Docker Compose）              │
│  ┌──────────────┐   ┌────────────────┐              │
│  │ 浏览器前端    │   │ 本地 Agent     │              │
│  │ (Vue SPA)    │   │ (ComfyUI + GPU)│              │
│  └──────┬───────┘   └────────┬───────┘              │
│         │                    │                      │
│  ┌──────▼────────────────────▼───────────────────┐ │
│  │  Nginx/Caddy（静态前端 + 反向代理）            │ │
│  │  ┌─────────────────────────────────────────┐  │ │
│  │  │ 后端 Express 5（业务 + 任务队列 + 存储）  │  │ │
│  │  │ AI 服务 FastAPI（LangChain + Milvus 检索）│  │ │
│  │  │ MySQL / Redis / Milvus(etcd+minio)       │  │ │
│  │  └─────────────────────────────────────────┘  │ │
│  └───────────────────────────────────────────────┘ │
│         │                                          │
│         ▼ (按配置调用云端 API，备选)                │
└─────────┼─────────────────────────────────────────┘
          │
          ▼
   ┌──────────────┐
   │  云端 AI API  │
   └──────────────┘
```

特点：全部服务通过 Docker Compose 编排在用户本机（前端/后端/AI/DB/队列/Milvus），ComfyUI 本地 GPU 生成，云端 API 按需调用（备选），数据不离开本机。

### 6.2 云端部署（后续扩展）

- Web 前端 + 云端服务部署至云服务器
- 本地 Agent 仍跑在用户 GPU 机器
- 支持多用户（协作扩展阶段）

## 7. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 架构形态 | 混合架构 | 重计算本地化（成本/隐私），轻交互云端化（协作/易用） |
| 前端形态 | **Vue 3 SPA**（Vite + Element Plus） | 用户指定；Web 展示，轻前端 |
| AI 接入 | Provider 抽象 + 可配置切换 | 解耦业务与具体模型，支持云端/本地按需切换 |
| 本地生成 | **ComfyUI 为主**（本地 V18.1） | 图像/视频生成本地化，工作流可编排、生态丰富；云端备选 |
| 记忆/向量库 | **Milvus**（standalone） | 用户指定；素材语义检索、角色一致性召回、项目记忆 |
| 数据库 | Prisma + MySQL（单机可 SQLite） | 参照 waoowaoo 双 schema；协作扩展无需换库 |
| 部署 | **Docker Compose 全栈** | 用户指定；一键编排前端/后端/AI/DB/队列/Milvus/ComfyUI |
| 协作扩展 | 数据模型预留作者字段 | MVP 单人，但为后续协作留扩展点 |
| 成片环节 | 本期不实现，预留导出 | 聚焦核心链路，素材以标准格式供下游剪辑 |
