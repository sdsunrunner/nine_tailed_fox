# AI 能力接入设计

> nine_tailed_fox — Provider 抽象层与本地 ComfyUI 为主、云端可切换

文档版本：v0.2（图像/视频以本地 ComfyUI 为主路径）
最后更新：2026-08-18

---

## 1. 设计目标

nine_tailed_fox 的 AI 能力采用 **Provider 抽象层** 统一接入，实现：

1. **能力统一** — 每类 AI 能力（文本/图像/视频/语音/音乐）定义统一接口，业务层不感知具体实现
2. **可配置切换** — 云端 API 与本地模型（ComfyUI）按能力维度配置切换
3. **可插拔扩展** — 新增 Provider 无需改业务代码
4. **降级与回退** — 主 Provider 不可用时可回退备选

## 2. AI 能力清单

| 能力 | 用途 | 云端 Provider 候选 | 本地 Provider 候选 |
|------|------|---------------------|---------------------|
| 文本生成 (LLM) | 选题/大纲/剧本/拆镜/续写改写 | GPT / Claude / 通义 / 智谱 | 本地 Qwen / Llama |
| 图像生成 | 角色形象/场景图/分镜图 | 即梦 / 可灵 / DALL·E / SD API | **ComfyUI** (SD/SDXL/Flux) |
| 视频生成 | 镜头视频片段 | 可灵 / 即梦 / Runway / Pika | **ComfyUI** (AnimateDiff/视频模型) |
| 语音合成 (TTS) | 角色对白配音 | 十一词 / Azure / 通义 TTS | 本地 TTS 模型 |
| 音乐生成 | 背景配乐 | Suno / 音乐 API | 本地音乐模型 |

> 本地多模态生成统一通过 **ComfyUI** 对接，涵盖图像与视频生成。
> **定位：图像/视频生成以本地 ComfyUI 为主路径**（本地部署 `H:\ComfyUI\ComfyUI-V18.1`），云端 API 作为备选/降级。

## 3. Provider 抽象架构

### 3.1 分层结构

```
┌─────────────────────────────────────────────────────────┐
│              业务层 (剧本/分镜/生成/设定)                │
│                  只调用统一能力接口                       │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│            AI 编排层 (Prompt / 参数构造 / 结果处理)      │
│   · 将业务请求转为 Provider 调用                          │
│   · 处理返回结果（解析/校验/入库）                        │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│            Provider 路由层 (能力 → Provider)              │
│   · 按能力查询当前配置的 Provider                         │
│   · 主备 Provider 切换/降级                              │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌──────────┬───────────────┬───────────────┬──────────────┐
│ 文本      │ 图像          │ 视频          │ 语音/音乐    │
│ Provider  │ Provider      │ Provider      │ Provider     │
│ (云端/本地)│(云端/ComfyUI) │(云端/ComfyUI) │(云端/本地)   │
└──────────┴───────────────┴───────────────┴──────────────┘
```

### 3.2 能力接口定义（概念）

每类能力定义统一接口，所有 Provider 实现该接口。以下为概念性描述（详设阶段补充字段/签名）：

#### 文本生成接口

```
输入：
  · system_prompt / user_prompt
  · 上下文（剧本/大纲/人物设定等结构化输入）
  · 输出格式要求（自然文本 / JSON 结构化）
  · 参数：温度、最大长度等

输出：
  · 文本内容（或结构化 JSON）
  · token 用量
  · Provider 元信息
```

#### 图像生成接口

```
输入：
  · 提示词（正向/负向）
  · 参考图（角色形象/场景图/参考风格，可选）
  · 视觉约束（锁定角色形象 ID、场景 ID）
  · 参数：宽高比、分辨率、采样步数、种子等

输出：
  · 图片 URL / 文件路径
  · 生成参数回显（便于复现）
  · Provider 元信息
```

#### 视频生成接口

```
输入：
  · 模式：图生视频 / 文生视频
  · 输入图（图生视频必填，通常为分镜图）
  · 提示词（运镜/动作描述）
  · 参数：时长、分辨率、帧率、种子等

输出：
  · 视频 URL / 文件路径
  · 生成参数回显
  · Provider 元信息
```

#### 语音合成接口

```
输入：
  · 文本（台词）
  · 音色 ID（与角色卡绑定）
  · 情绪/语速/音调参数

输出：
  · 音频 URL / 文件路径
  · 时长
  · Provider 元信息
```

#### 音乐生成接口

```
输入：
  · 氛围/风格描述
  · 时长
  · 参考曲风（可选）

输出：
  · 音频 URL / 文件路径
  · Provider 元信息
```

## 4. Provider 路由与配置

### 4.1 配置模型

每个能力维度独立配置主/备 Provider：

```yaml
# 概念性配置示例（详设阶段确定格式）
capabilities:
  text_generation:
    primary: cloud_openai_gpt4
    fallback: local_qwen
  image_generation:
    primary: local_comfyui_image
    fallback: cloud_jimeng
  video_generation:
    primary: local_comfyui_video
    fallback: cloud_kling
  tts:
    primary: cloud_elevenlabs
    fallback: null
  music:
    primary: cloud_suno
    fallback: null
```

### 4.2 路由逻辑

```
业务请求 (能力, 输入)
   ▼
查询该能力的当前 Provider 配置
   ▼
调用主 Provider
   ├── 成功 → 返回结果
   ├── 失败/超时 → 检查是否有备选 Provider
   │              ├── 有 → 调用备选 Provider
   │              └── 无 → 任务失败，记录错误
   └── 任务进入异步队列（图像/视频/音乐）
```

### 4.3 用户配置入口

用户在「设置 > AI Provider 配置」页面（见 [04-Pages-Structure.md](./04-Pages-Structure.md#38-ai-provider-设置)）：
- 为每个能力选择主/备 Provider
- 配置云端 API Key
- 配置本地 Agent 与 ComfyUI 地址
- 测试连接

## 5. ComfyUI 对接设计

### 5.1 ComfyUI 角色

ComfyUI 作为本地多模态生成的统一执行引擎，承载：
- **图像生成**：角色图、场景图、分镜图（基于 SD/SDXL/Flux 等模型）
- **视频生成**：镜头视频片段（基于 AnimateDiff、视频生成模型等）

### 5.2 对接架构

```
云端服务 (AI 编排层)
   │
   │  生成任务（图像/视频）
   ▼
本地 Agent
   │
   │  调用 ComfyUI API
   ▼
ComfyUI (http://localhost:8188)
   │
   │  加载工作流模板 + 注入参数
   ▼
执行工作流 → 输出图像/视频
   │
   ▼
本地 Agent 回传结果（文件路径/上传至服务层）
```

### 5.3 工作流模板机制

针对不同生成场景，预置 ComfyUI 工作流模板：

| 模板 | 用途 | 关键节点 |
|------|------|----------|
| character_image | 角色形象生成 |Checkpoint + Prompt + IPAdapter(一致性) |
| scene_image | 场景图生成 | Checkpoint + Prompt + ControlNet(可选) |
| storyboard_image | 分镜图生成 | Checkpoint + Prompt + IPAdapter(角色/场景约束) |
| img2video | 图生视频 | AnimateDiff / 视频模型 + 输入图 |
| txt2video | 文生视频 | 视频模型 + Prompt |

**模板设计要点**：
- 模板为 ComfyUI 工作流 JSON，参数化变量（提示词/参考图/种子/尺寸等）
- 业务层提交任务时，传入参数，由 Agent 填充到模板对应节点
- 支持用户自定义/替换工作流模板（高级用法）

### 5.4 一致性约束实现

角色/场景一致性是短剧生成的核心诉求，通过以下机制实现：

| 约束类型 | 实现方式 |
|----------|----------|
| 角色形象一致 | IPAdapter / 参考图作为条件输入；锁定角色形象 ID |
| 场景一致 | 场景图作为参考输入到分镜生成 |
| 风格一致 | 全局风格 LoRA / 统一 Checkpoint / 风格参考图 |
| 种子复用 | 同一角色/场景的生成固定种子，确保可复现 |

### 5.5 任务执行流程

```
1. 业务层提交生成任务（含模板名 + 参数）
2. Provider 路由到 local_comfyui
3. 任务下发至本地 Agent
4. Agent 加载工作流模板，填充参数
5. Agent 调用 ComfyUI API (/prompt) 提交工作流
6. ComfyUI 执行，Agent 轮询状态
7. 完成后，Agent 获取输出文件
8. Agent 回传：文件路径 + 元信息
9. 服务层入库，WebSocket 推送进度/完成
```

### 5.6 错误处理

| 错误场景 | 处理 |
|----------|------|
| ComfyUI 不可达 | 标记 Agent 离线，任务排队等待或回退云端 |
| 工作流执行失败 | 记录 ComfyUI 错误日志，任务标记失败，可重试 |
| 显存不足 | 提示用户，可选降分辨率/换轻量模型 |
| 超时 | 任务超时取消，标记失败 |

## 6. 云端 API Provider 对接

### 6.1 通用对接模式

每个云端 API Provider 实现对应能力接口，封装：
- 认证（API Key）
- 请求构造（适配各家 API 格式）
- 响应解析（统一为内部格式）
- 错误处理与重试
- 计费/配额感知（可选）

### 6.2 凭据管理

- API Key 加密存储，不在前端暴露
- 后端服务代理调用，前端不直接请求云端 API
- 支持多 Provider 各自独立凭据

### 6.3 异步任务

云端 API 中，图像/视频/音乐生成通常为异步：
1. 提交任务 → 返回任务 ID
2. 轮询 / 回调查询状态
3. 完成后获取结果 URL
4. 下载并入库

服务层统一封装为内部任务队列模型，对业务层透明。

## 7. 任务编排模型

### 7.1 任务统一抽象

所有 AI 生成操作（无论云端/本地）统一为「任务」：

```
Task {
  id, type (能力), provider, status,
  input (参数), output (结果),
  progress, error,
  created_at, updated_at,
  source (业务来源：镜头ID/角色ID/场景ID)
}
```

### 7.2 任务状态机

```
排队中 (queued)
   │
   ▼
执行中 (running) ── 失败 ──> 失败 (failed) ── 重试 ──> 排队中
   │
   ▼
成功 (succeeded)
   │
   ├── 用户采用 ──> 已选用 (adopted)
   └── 用户废弃 ──> 已废弃 (discarded)
```

### 7.3 批量任务

支持批量提交（如「批量生成故事板」「批量生成视频」）：
- 一个批量任务包含多个子任务
- 子任务独立执行、独立失败、独立重试
- 批量任务汇总进度

### 7.4 并发控制

- 本地 Agent 并发数受 GPU 显存限制，可配置最大并发
- 云端 API 并发受 Provider 限流，按需排队
- 任务队列按优先级调度

## 8. Provider 扩展指南

新增一个 Provider 的步骤：

1. **实现能力接口** — 新建 Provider 类，实现对应能力接口
2. **注册 Provider** — 在 Provider 注册表登记（能力 + 标识 + 元信息）
3. **配置凭据/参数** — 在设置页暴露配置项
4. **测试验证** — 提供测试用例，验证生成效果
5. **可选：贡献工作流模板**（ComfyUI 类 Provider）
